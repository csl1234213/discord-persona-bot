# 維護更新

客戶自行保管Token、資料與備份。先小範圍試運行，遇到越權、秘密外洩或資料異常立即停止。

## 停止服務

在安裝資料夾執行：

```powershell
docker compose -p persona-customer -f compose.release.yml stop
```

不要執行 `down -v`，它會刪除資料卷。停止後的退出碼不保證所有背景操作已優雅完成。

## 保管備份

先停止Bot，確認容器已退出，再備份整個 `/app/data`，包含存在的SQLite主檔、WAL及SHM。
不要在聊天仍寫入時只複製一個DB檔。備份放客戶自己的加密位置，不上傳GitHub。
另行私密保管設定與密鑰，不打包進公開問題回報或程式更新。
依PRIVACY.md保留最多3份、7天；處理刪除要求時也要處理舊副本。

不同主機的資料卷位置不同；未確認目標前不要使用網上複製來的刪除或還原指令。
完整備份還原尚未由獨立客戶主機驗收，正式承載重要資料前必須先演練。

## 安排更新

1. 取得新交付包與CHECKSUMS，核對程式與映像摘要。
2. 在新資料夾及獨立資料卷先測試，不共用正式設定或資料。
3. 記下目前的image ID和資料庫版本，停止正式Bot並備份。
4. 確認更新說明是否涉及資料庫變更，才安排停機更新。
5. 載入新映像，將persona-release-audit:local標記到新image ID。
6. 在原安裝資料夾，以同一persona-customer專案名及安全設定重新啟動。
7. 核對Discord就緒、一次回覆、管理限制及資料保存，異常立即停止。

不要在未知版本間直接覆蓋設定或移除安全檢查。程式變更後舊測試結果不自動適用。

## 回到舊版

先停止新Bot，保留錯誤證據。在隔離位置測試舊映像和相符資料庫備份，再安排恢復。
只切換舊映像不一定相容新資料庫；資料庫升級後通常需配套還原。
不得讓新舊Bot同時寫入同一資料庫。
恢復舊備份可能帶回已刪除會話與舊額度，需重新落實刪除要求及安全計數後再開放。

## 資料刪除

`/chat-reset`只重新開始聊天，保留舊記錄。
`/chat-erase`刪除本人在指定伺服器/頻道的本地會話，不刪人物資料、Discord原訊息或短期安全額度。
本機刪除不代表SSD法證擦除；未知備份、Discord及模型服務端記錄需另行處理。
